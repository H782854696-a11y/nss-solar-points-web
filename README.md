# NSS Solar 中控平台 V2

本项目由 NSS Solar 原 SolarPoints 源码改造为独立中控平台。集团中控负责远程审批、任务协作、门店跟进、通知和审计；金蝶云星辰继续作为正式财务、销售、商品和进销存系统。

## 当前范围与状态

- 集团中控是唯一管理主板块；不建立独立“经营”板块。
- 当前源码（基线 `8ae77b3`）允许新建五类流程：库存盘点、门店整改、费用报销、订单优惠申请、门店收货确认。旧类别和历史记录仍兼容保留。
- 每个流程类型的新定义只配置一名具体审批人；候选人和后续操作仍受既有 RBAC 与数据范围校验。已在途实例继续使用创建时的 `approvalSteps` 快照及原有多级/会签行为，不迁移、不重写。
- 费用报销新单只填写 PHP 报销金额、费用说明和 PNG/JPG 图片凭证；金额必须为精确正数、最多两位小数且不低于最小单位。门店归属来自既有范围：单门店账号自动使用唯一门店，多门店账号必须明确选择，绝不暗中默认。
- 盘点申请可直接附上任意排版的 Excel（XLSX、XLS、XLSM、XLSB）或 CSV 原文件供审批人下载；不检查表头、工作表或盘点行。单文件最大 10MB，手工明细可选；系统仍会核对文件类型和大小。
- 不维护中控专用的门店/店长或仓库/负责人主档，不重复实现金蝶已有的财务、销售、商品和库存账。
- 不接入金蝶 API。需要时，工作人员手工登记外部单据编号和执行状态。
- 创建账号、重置密码、首次登录改密和个人改密的最短密码长度为 6 位；服务器首次初始化专用的 `SP_ADMIN_PASSWORD` 环境变量仍要求至少 16 位。
- 管理员新建账号或重置他人密码后，账号可直接登录；个人账号设置仍要求验证当前密码，并会作废旧会话。首次初始化管理员及仍使用旧 `admin123` 默认凭据的账号继续强制改密。生产迁移只解除已标记的活动普通员工账号（店长、销售、仓储、售后、采购）；所有管理层、停用和未知角色账号均保守跳过。
- 2026-10-07 版本下线旧版会员积分：入口、公开查询及积分 API 均不可访问；积分专属数据在发布后按 `deploy/purge-legacy-points.js` 清理。门店和账号属于中控共用资料，继续保留。
- 首页采用紧凑仪表盘：待办数字、单行公告、快捷办理、最近事项与待办提醒。2026-10-07 UI 评审整改增加蓝色视觉令牌、深色侧栏与可切换深色模式、加载骨架、侧栏待办角标及键盘导航；最近事项独立读取未筛选记录并按时间排序。第二轮全站整改增加导航层级、真实数据统计卡、状态与期限标记、任务清单进度、空状态、分页、必填提示和盘点拖放上传区；设计稿中的虚构指标未上线。公告支持草稿、发布、置顶和归档；发布/编辑权限授予总部管理员、集团负责人、总部运营和菲律宾管理负责人。
- 「日常运营 → 当日存款」按菲律宾日期汇总各门店的未存款、待审核、已确认和已驳回状态。总部与区域管理人员可对未上报门店提醒店长；提醒会生成店长待办任务和站内通知，10 分钟内不能重复发送。店长提交时必须上传 JPG/JPEG/PNG 格式、最大 5MB 的银行存款凭证图片；具备 `deposit.review` 权限的管理员可在当前页面的预览弹窗中确认或驳回。驳回必须填写原因，店长可重新提交，原凭证文件及元数据会保留。待办只会在审核确认后完成。该状态是门店自报与内部凭证审核，不是银行到账核验；本模块不记录金额，也不替代金蝶账务。历史 `reported` 记录按已确认兼容显示，历史未完成的存款待办会在次日自动关闭并通知原提醒人。
- 当前实现和产品边界见 [README-V2.md](README-V2.md)、[ARCHITECTURE-V2.md](ARCHITECTURE-V2.md) 与 [IMPLEMENTATION-STATUS.md](IMPLEMENTATION-STATUS.md)。完整状态、验证记录和交接步骤见 [HANDOFF.md](HANDOFF.md)。

## 架构与技术栈

- Node.js + Express 服务端，静态前端位于 `public/`。
- `server.js` 提供登录、权限、审批、任务、通知、门店跟进和审计 API。
- `lib/` 按审批、权限、存储、报表、审计和提醒等职责拆分业务逻辑。数据可使用 JSON 存储或 Node 内置 `node:sqlite` SQLite 驱动。
- `public/` 包含管理界面、样式、双语资源和 PWA manifest/service worker。PWA 可缓存页面外壳，离线时可匹配带版本参数的静态资源；只清理本应用旧缓存，不删除同域其他应用缓存。业务 API 仍需联网。
- `deploy/` 保存 V2 独立目录发布、备份、只读预检、积分专属数据清理和 PM2 配置辅助脚本。2026-10-05 已用这些脚本发布到服务器，详细结果见 [HANDOFF.md](HANDOFF.md)。
- 主要运行依赖列于 `package.json` 与 `package-lock.json`：Express、cookie-parser、bcryptjs、nanoid。

## 前置环境与安装

需要 Node.js 22.5–24.x（使用内置 `node:sqlite` 时）；项目声明 npm 10.9.x。此持久化本地 worktree 已保存忽略的项目级 npm 10.9.8 工具，未安装或声明全局 npm、也未修改系统 PATH。准确的本地工具路径和复跑命令见 [LOCAL_ENV_TESTING.md](LOCAL_ENV_TESTING.md)。安装依赖：

```sh
npm ci
```

使用官方 npm registry 或已有锁文件缓存；不要删除或重写 `package-lock.json` 来绕过安装问题。正式环境仍以 `npm ci` 为准。

## 本地配置与启动

复制 `.env.example` 为 `.env`，将初始化密码替换为只在本地使用的随机强密码（至少 16 个字符）。应用不会自动读取 `.env`，启动前需在 shell 中加载它：

```sh
cp .env.example .env
# 编辑 .env，替换 SP_ADMIN_PASSWORD
set -a
. ./.env
set +a
npm start
```

Windows PowerShell 可直接设置环境变量后运行 `npm start`。不要把 `.env`、初始管理员凭据或运行数据提交到版本库。`SP_DATA_DIR` 应始终指向独立的本地目录，不能指向生产服务器数据；首次初始化产生的 `INITIAL_ADMIN_CREDENTIALS.txt` 是敏感凭据，应妥善保管并在首次登录后改密。设置 `SP_ADMIN_PASSWORD` 只影响新初始化的数据目录。

默认本地地址为 `http://localhost:3000`。`PORT` 可改为其他未占用端口。`npm run dev` 会默认使用被忽略的 `.local-data/`；非空的外部 `SP_DATA_DIR` 始终优先。`npm start` 保持生产启动行为，仍要求调用方显式提供合适的数据目录。

## 常见问题

- **启动时提示缺少模块**：在项目根目录运行 `npm ci`，确认 npm 网络可用。
- **提示端口已占用**：修改 `PORT` 为其他空闲端口，并用相同地址访问。
- **误把资料写进项目目录**：为 `SP_DATA_DIR` 设置明确的本地隔离路径；不要使用生产路径。`.local-data/` 已加入忽略规则。
- **`.env` 修改后配置没有生效**：本项目不自动加载 `.env`；按上面的 shell 命令加载后再启动。
- **手机离线时流程无法提交**：PWA 只缓存页面外壳，审批、通知和附件 API 需要网络连接。
- **浏览器仍显示旧页面**：强制刷新页面并重新登录；若 PWA 仍缓存旧版，关闭后重新打开。当前 UI 评审整改资源版本为 `app.js?v=64`，PWA 缓存版本为 26；若依旧显示旧版，再检查浏览器缓存和 service worker。
