# NSS Solar Group Control Center V2

## 当前工作状态

本目录是用户现有 NSS Solar 系统的开发源码。2026-10-02 曾按此前范围部署过 V2 基础版；2026-10-04 起按用户最新确认缩小审批范围、收敛中控架构。2026-10-05 已发布收敛后的 V2；后续功能是否在线以 `HANDOFF.md` 的最新发布记录和实际公网检查为准。

## 已确认的产品边界

- “集团中控”是唯一管理主板块。中控内分总览、审批中心、任务与通知、门店跟进、审计与设置工作区。
- 只保留库存盘点申请审批、门店整改两个新流程。
- 采购、费用报销、付款、库存调拨、库存调整、价格调整六类不再接受新单；旧记录在界面只读归档。
- 不建设门店/店长或仓库/负责人档案管理，不重复金蝶正式进销存、销售、商品和财务功能。
- 金蝶云星辰不接任何 API。获批后的外部单据编号与执行状态由管理人员手动回填。
- 既有会员积分功能保持独立，与集团审批数据分开。

## 当前实现功能

- 通用审批引擎：顺序审批、任一人通过/全部会签、退回、驳回、重提、撤回、流程备注、附件、审批名额委托、外部单据关联、操作审计。审批路径支持角色或指定账号、保存前预览、版本快照和 1–720 小时 SLA 提醒；提醒只发给当前步骤尚未签署且有查看/审批权限的人员。
- 库存盘点申请：可原样上传任意排版的 XLSX/XLS/XLSM/XLSB 或 CSV，系统不检查表头、工作表和盘点行内容；审批人可下载原文件。单文件上限 10MB。手动填写结构化明细仍可选，最多 2,000 行；若填写则校验编码、数量和差异原因，并支持预览及 CSV 导出。获批后登记外部单据编号及执行状态，不写库存余额。
- 门店整改：记录地点、问题描述和期限；可在申请时指派负责人，也可由有任务指派权限的管理人员在批准后指派或更换负责人。负责人收到通知并在期限内补交整改资料。附件分为整改前、整改后和其他凭证；前后证据必须由当前负责人在执行阶段上传并归属于当前整改轮次。更换负责人且已有本轮前后证据时开启新轮次，避免沿用前任凭证。复查退回也会开启新轮次，缺少本轮前后证据时服务端不允许再次提交复查或关单。复查人可通过关闭或退回整改，全过程留痕。隔离数据目录中的多账号 API 验收已覆盖执行闭环；浏览器页面已走通批准、指派、提交复查和确认关闭。测试凭证通过隔离 API 上传，文件选择框的手工上传仍待验收。
- 任务与门店协作：任务指派、截止日和优先级、按状态/优先级/门店筛选与搜索、逐行执行清单、逐项操作人/时间记录、任务评论、完成凭证、结项校验、日报、巡检、问题跟进、站内通知、逾期提醒和操作审计。审批、任务、通知、日报、巡检和历史问题列表均由服务端分页。审计可按关键词和日期范围筛选、分页查看。任务最多 40 项清单；未完成时服务端拒绝结项。任务凭证支持 PDF、PNG/JPG、CSV、XLSX，单文件最大 4MB；日报与巡检支持多文件 PDF、PNG/JPG 凭证，每条记录最多 10 个文件、合计 20MB。
- 旧版独立门店问题登记/关闭接口已停用，历史问题只读保留；新问题统一通过“门店整改”流程发起，避免绕过审批和证据复查。
- 门店整改联动：巡检不合格或需关注可直接发起整改申请，来源巡检和凭证自动关联；每条巡检最多只允许存在一个未完成整改申请，避免重复开单。
- PWA 安装外壳：缓存静态页面资源，离线匹配带版本号的脚本与样式；缓存升级仅清理本应用的旧缓存，不碰同域会员系统缓存。API 读写仍要求在线。
- 中控内不新增门店或仓库主档。旧会员模块仍保留自己的关联数据，不因本次本地改造而迁移或删除。

尚未纳入本次已确认业务范围的增强项：任务模板/周期任务、外部推送渠道、审计 CSV 导出。它们不影响盘点和门店整改闭环。每次新版本发布前仍需核对代码、备份与回滚；实际账号逐角色和手机端验收仍需完成。

## 部署与数据安全

生产域名为 `nss-solar-points.com`。V2 位于腾讯云轻量主机独立目录 `/opt/solarpoints-v2/`，PM2 进程为 `solarpoints-v2`，监听本机 3001 端口；此前 `/opt/solarpoints/` 和会员积分 SQLite 数据另行保留。2026-10-05 发布未更改 DNS、证书或旧会员数据；后续发布须核对实际状态。

如需本地运行，使用独立数据目录 `SP_DATA_DIR=/absolute/path/to/local-data`，勿指向生产路径。首次初始化的随机临时管理员凭据会写在该本地数据目录的 `INITIAL_ADMIN_CREDENTIALS.txt`；不要把此文件加入源码包或提交版本库。也可通过环境变量 `SP_ADMIN_PASSWORD` 设置至少 16 位的本地初始化密码。首次登录必须改密。

源码包提供安全的 V2 发布脚本 `deploy/deploy-v2.sh`：上传隔离版本到 `/opt/solarpoints-v2/releases/`，保留共享数据目录，发布前做限权备份，切换 PM2 到新版本并检查本机健康页，失败则恢复上一版本。脚本不会改动 `/opt/solarpoints/`、旧会员积分数据、Nginx、DNS 或证书。需要主机可用的 SSH 发布密钥才能执行；脚本不会读取或包含本地凭据文件。
